Current eight-client scope: [native API routing, account login and guarded history resume](cli-router-focus-eight.md).

Documentation review: 2026-10-04. This records candidate contracts and outstanding
implementation gates. It does not declare unimplemented adapters usable or prove
account availability, quota independence, permitted subscription use or continuity.
Implementation and source review of the current phase finished before its test
gate reopened. Offline parser/history/UI tests and isolated installed-client
version probes passed; see the [validation record](cli-router.md#validation-record).
No authentication/provider calls, configured profiles or live paid qualification
are available.

mediated Codex coding have separate contracts below; a text-mode blocker does not

Each gateway account profile carries an explicit HTTPS API destination and
protocol. The native owner starts an authenticated loopback gateway and a private
TTY, clears the child environment, and emits a fresh private HOME/config containing
only a local ephemeral client token. Provider keys stay native-side. Native tools,
permission prompts, compaction and history remain in the same CLI process while
eligible HTTP requests switch accounts. This mode does not apply the mediated
four-file-tool policy or claim to sandbox native plugins, shells or external tools.

Changing a profile API endpoint disconnects its retained old key. The new
destination remains disconnected until an API key is explicitly saved for it;
endpoint changes do not silently reuse credentials.

Account switching is limited to an explicit upstream HTTP 429 before a response
has been forwarded. Partial responses, ambiguous transport failures and tool
execution are never replayed by the gateway. After the first successful response,
Responses, Gemini and custom Anthropic destinations retain account affinity.
Native Anthropic pools at `api.anthropic.com` pass thinking blocks and signatures
through unchanged. Anthropic documents opaque signature preservation and platform
portability; extending that to different accounts at the same API origin is a
source-based inference, **not a real A/B result**. See
[extended thinking](https://platform.claude.com/docs/en/docs/build-with-claude/extended-thinking)
and [thinking encryption](https://platform.claude.com/docs/en/build-with-claude/thinking#thinking-encryption).

Same-protocol Gateway traffic retains exact bytes. Canonical text/function-tool
conversion is implemented for all 12 directed pairs across Anthropic Messages,
OpenAI Chat, OpenAI Responses and Gemini, with validated buffered terminal SSE.
This public subset does not admit every native CLI feature: unsupported opaque
context, encrypted reasoning, signatures, hosted/custom grammar tools and options
are rejected before dispatch, and cross-protocol token counting is unsupported.
Actual Codex 0.160.0 requires Responses destinations because its mandatory native
reasoning/context defaults have no documented equivalent in the other protocols.
Other focused clients expose four choices subject to per-request validation.
Explicit custom HTTPS destinations still require provider support for the admitted
features. Model/files/attachments and auxiliary cloud endpoints require
per-client workflow qualification. Project dotenv/config overrides and fixed
managed policy are admitted before key access and launch, and again at the owner
fence. Python Kimi 1.52.0 and npm Kimi Code 2.1.1 are distinct client families;
Python Open Interpreter 0.4.3 and deployment-only `deepagents-cli` must likewise not
be substituted for their listed family.

Save/Stop retains native HOME and history only after the HTTP request journal and
PTY output tail fully drain with the process group. An incomplete drain requires
explicit Recovery. The eight focused clients now support explicit guarded native
history resume after clean Stop, using existing conversation/session identities.
Client/version/workspace/model and creator credential bindings must match. Missing
or uncertain history is retained without a new invented conversation. See the
[exact continuation gates](cli-router-focus-eight.md#account-selection-and-continuation).

Qwen pins its main, fast, compaction and vision models to one Chat provider in
private highest-priority system settings. Project `.env`, `.qwen/.env` and
`.qwen/settings.json` overrides must be absent; its separate DashScope web-search

## Common admission gates

Managed text and mediated coding adapters need an isolated credential/state namespace without fallback,
authenticated principal identity, provider/model compatibility, qualified quota
scope and structural exhaustion signals. Process cancellation must drain all owned
work before another account receives context. Provider-supported continuation or
an explicit reviewed handoff must define what happens to prior tool results.

An internal tool/startup effect requires a pre-execution fence or durable provider
journal. Observing a tool event after execution is insufficient. Read-only does
not imply secrets cannot be read. Extension loading, hooks, skills, MCP and
daemon attachment require qualification independently of tool-call permissions.
